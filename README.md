## امکانات

### پایش Uptime

- پشتیبانی از `http` و `https` با متد `GET` و دنبال‌کردن امن ریدایرکت‌ها (حداکثر ۵ مرحله).
- بازه بررسی هر دامنه مستقل است؛ پیش‌فرض **۶۰ ثانیه**.
- تنظیم `timeout`، آستانه کندی (Degraded) و تعداد شکست متوالی لازم برای اعلام Down (پیش‌فرض **۳**).
- وضعیت‌ها: `Up`، `Degraded`، `Down` و `نامشخص` (قبل از اولین بررسی).
- ذخیره تاریخچه هر بررسی: زمان، موفقیت، کد HTTP، زمان پاسخ و نوع/متن خطا.
- محاسبه درصد Uptime برای **۲۴ ساعت، ۷ روز و ۳۰ روز** بر اساس تاریخچه واقعی بررسی‌ها.
- نمایش نمودار کوچک ۳۰ بررسی اخیر و زمان پاسخ.

### پایش SSL

- پایش کاملاً مستقل از Uptime و با بازه پیش‌فرض **۵ دقیقه**.
- بازه سراسری و بازه اختصاصی هر دامنه، قابل تغییر از پنل مدیریت **بدون ری‌استارت**.
- بررسی موارد زیر:
  - تاریخ انقضا و تعداد روز باقی‌مانده
  - تطابق نام دامنه با گواهی (hostname mismatch)
  - گواهی self-signed
  - زنجیره گواهی نامعتبر/ناشناخته
  - شکست handshake
  - نسخه TLS (نسخه‌های قدیمی‌تر از 1.2 هشدار می‌گیرند)
- هشدار انقضا در آستانه‌های **۳۰، ۱۴، ۷ و ۱ روز**؛ هر آستانه برای هر گواهی فقط **یک بار** ارسال می‌شود.

### داشبوردها

- دو صفحه مستقل: **وضعیت سایت‌ها** و **وضعیت SSL**.
- جستجو روی نام، آدرس، دسته، برچسب، صادرکننده و متن خطا.
- فیلتر وضعیت و دسته، مرتب‌سازی ستون‌ها، به‌روزرسانی خودکار (۲۰ ثانیه) و دکمه به‌روزرسانی دستی.
- کارت‌های خلاصه وضعیت.
- تاریخ شمسی با امکان تغییر به میلادی در همان صفحه (ذخیره انتخاب در مرورگر).
- طراحی واکنش‌گرا برای موبایل و دسکتاپ.

### هشدارها

- قطعی سرویس (پس از رسیدن به آستانه شکست).
- بازگشت سرویس همراه با مدت قطعی.
- مشکل گواهی SSL و رفع آن.
- نزدیک شدن انقضای SSL.
- کانال‌ها: **ایمیل (SMTP)**، **تلگرام** و **وب‌هوک عمومی**.
- صف ارسال با تلاش مجدد و backoff؛ جلوگیری از ارسال تکراری با کلید یکتای رویداد.
- تمام رمزها/توکن‌ها فقط از متغیرهای محیطی خوانده می‌شوند و در دیتابیس ذخیره نمی‌شوند.

### مدیریت

- افزودن، ویرایش و حذف دامنه؛ نام نمایشی، دسته، برچسب، فعال/غیرفعال بودن و تنظیمات هر پایش.
- افزودن گروهی از متن چسبانده‌شده یا فایل CSV با اعتبارسنجی، حذف تکراری‌ها و گزارش کامل نتیجه.
- مدیریت کاربران با نقش `admin` یا `viewer`.
- تغییر رمز عبور شخصی و بسته‌شدن سایر نشست‌ها.
- تنظیمات سراسری پایش، نگهداری تاریخچه و اجازه دسترسی به آدرس‌های خصوصی.

## معماری

```
مرورگر (HTML/CSS/JS بدون build)
        │  HTTPS + کوکی نشست + CSRF
        ▼
   Express 5 (app)
        │
        ├── PostgreSQL 16  ◀── migrations با advisory lock
        │        ▲
        │        │ claim با FOR UPDATE SKIP LOCKED
        │   Worker (پایشگر)
        │        ├── بررسی‌های uptime (موازی و محدود)
        │        ├── بررسی‌های SSL
        │        └── ارسال صف هشدارها
        │
        └── SMTP / Telegram / Webhook
```

- **app** فقط API و فایل‌های استاتیک را سرو می‌کند.
- **worker** جداگانه اجرا می‌شود و کارهای سررسیده را از دیتابیس claim می‌کند؛ بنابراین افزودن نمونه دوم باعث بررسی تکراری نمی‌شود.
- هر بررسی Uptime با `http/https` و IP اعتبارسنجی‌شده و pin‌شده انجام می‌شود تا از DNS rebinding جلوگیری شود. بررسی SSL با `tls.connect` به همان IP و با SNI صحیح انجام می‌شود.
- وضعیت Uptime و SSL در ستون‌های جداگانه ذخیره می‌شود و بر هم اثر ندارند.

## راه‌اندازی سریع با Docker

### ۱) پیش‌نیاز

- Docker Engine و Docker Compose v2

### ۲) ساخت فایل تنظیمات

```bash
cp .env.example .env
```

سپس در `.env` حداقل این مقادیر را حتماً تغییر دهید:

```env
POSTGRES_PASSWORD=یک-رمز-تصادفی-قوی
DATABASE_URL=postgresql://uptime:همان-رمز-تصادفی@db:5432/uptime
ADMIN_PASSWORD=یک-رمز-قوی-حداقل-۱۰-کاراکتری-با-حرف-و-رقم
SESSION_COOKIE_SECURE=false
```

> اگر سامانه پشت HTTPS است، `SESSION_COOKIE_SECURE=true` و در صورت وجود reverse proxy، `TRUST_PROXY=true` را تنظیم کنید.

### ۳) اجرا

```bash
docker compose up -d --build
```

این فرمان:

1. PostgreSQL را بالا می‌آورد و سالم بودنش را بررسی می‌کند.
2. migrationها را با advisory lock اجرا می‌کند (هم در app و هم worker، به‌صورت ایمن).
3. ادمین اولیه را در صورت تنظیم `ADMIN_PASSWORD` می‌سازد.
4. app را روی پورت `HOST_PORT` (پیش‌فرض ۳۰۰۰) و worker را اجرا می‌کند.

سپس وارد شوید:

```
http://localhost:3000
```

### ۴) توقف و پاک‌سازی

```bash
docker compose down          # توقف
docker compose down -v       # توقف + حذف داده‌ها (احتیاط)
```

## راه‌اندازی بدون Docker

پیش‌نیاز: Node.js ۲۲ یا بالاتر و PostgreSQL ۱۴ یا بالاتر.

```bash
# ۱) نصب وابستگی‌ها
npm install

# ۲) تنظیم محیط
# .env بسازید و DATABASE_URL را به PostgreSQL محلی اشاره دهید
DATABASE_URL=postgresql://uptime:password@localhost:5432/uptime

# ۳) اجرای migrationها
npm run migrate

# ۴) ساخت ادمین اولیه
ADMIN_PASSWORD='رمز-قوی-شما' npm run seed:admin

# ۵) اجرای سرور
npm start

# ۶) در ترمینال دیگر اجرای worker
npm run worker
```

برای ساخت مجدد رمز ادمین:

```bash
ADMIN_PASSWORD='رمز-جدید' npm run seed:admin -- --force
```

> `--force` رمز را عوض می‌کند، نقش را admin می‌کند و همه نشست‌های آن کاربر را می‌بندد.

## افزودن و ورود گروهی دامنه‌ها

### افزودن تکی

از **مدیریت ← دامنه‌ها ← افزودن دامنه**. با ثبت هر دامنه، هر دو پایش Uptime و SSL به‌طور خودکار ساخته می‌شوند (قابل غیرفعال‌کردن).

### متن چسبانده‌شده

در مودال **افزودن گروهی**، هر خط یک دامنه است:

```text
example.com
https://bank.example.ir | نام نمایشی | بانک‌ها | پرداخت، عمومی
shop.example.com,فروشگاه,فروشگاه‌ها
```

قالب: `آدرس | نام | دسته | برچسب‌ها`

- جداکننده `|` یا `,` است.
- خطوط خالی و خطوطی که با `#` شروع می‌شوند نادیده گرفته می‌شوند.
- حداکثر ۲۰۰۰ ردیف در هر درخواست پردازش می‌شود.

### فایل CSV

ستون‌های شناخته‌شده (حساس به حروف بزرگ/کوچک نیست):

```csv
url,name,category,tags,allow_private
https://example.com,سایت اصلی,عمومی,"پرداخت,عمومی",false
example.ir,فروشگاه,فروشگاه‌ها,,false
```

- اگر سطر هدر وجود نداشته باشد، ترتیب ستون‌ها `url,name,category,tags` است.
- فایل حداکثر ۲ مگابایت و UTF-8 (با یا بدون BOM).
- ورودی‌های تکراری در فایل و تکراری‌های موجود در دیتابیس گزارش می‌شوند و دوباره ثبت نمی‌شوند.
- آدرس‌های بدون `scheme` به‌صورت خودکار با `https://` تکمیل می‌شوند.
- در پایان گزارش «افزوده‌شده / تکراری / نامعتبر» با شماره خط نمایش داده می‌شود.

## کانال‌های هشدار

### ایمیل (SMTP)

```env
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=alert@example.com
SMTP_PASS=...
SMTP_FROM=alert@example.com
ALERT_EMAIL_TO=ops@example.com
```

### تلگرام

```env
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_CHAT_ID=-1001234567890
```

ربات باید عضو چت/کانال باشد و امکان ارسال پیام داشته باشد.

### وب‌هوک عمومی

```env
WEBHOOK_URL=https://hooks.example.com/didehban
WEBHOOK_SECRET=یک-کلید-تصادفی
```

درخواست `POST` با بدنه JSON:

```json
{
  "id": 12,
  "kind": "uptime_down",
  "severity": "critical",
  "title": "🔴 قطعی: سایت اصلی",
  "body": "…",
  "meta": { "targetId": 1, "url": "https://example.com" },
  "createdAt": "2026-01-01T00:00:00.000Z"
}
```

اگر `WEBHOOK_SECRET` تنظیم شده باشد، هدر زیر ارسال می‌شود:

```
X-Didehban-Signature: sha256=<HMAC-SHA256 بدنه خام با کلید>
```

### افزودن کانال جدید

۱. در `src/services/notifiers.js` یک شیء با متد `send(event)` اضافه کنید.
۲. آن را در `src/config.js` (خواندن env و `enabledAlertChannels`) فعال کنید.
۳. نام کانال به‌صورت خودکار در صف `notifications` استفاده می‌شود؛ نیازی به تغییر worker نیست.

## نقش‌ها و امنیت

### نقش‌ها

| نقش | دسترسی |
|---|---|
| `admin` | مشاهده داشبوردها + مدیریت دامنه‌ها، کاربران و تنظیمات |
| `viewer` | فقط مشاهده داشبوردهای Uptime و SSL |

- کنترل دسترسی در سمت سرور روی همه مسیرهای `/api/admin/*` با `requireAdmin` اعمال می‌شود؛ مخفی‌کردن دکمه در UI کافی نیست.
- صفحه `/admin` برای بیننده به `/dashboard` هدایت می‌شود.
- حذف یا غیرفعال‌کردن آخرین ادمین فعال ممکن نیست.
- هر کاربر نمی‌تواند نقش/فعال‌بودن حساب خودش را محدود کند.

### امنیت پیاده‌سازی‌شده

- **رمز عبور:** bcrypt با cost ۱۲؛ سیاست حداقل ۱۰ کاراکتر شامل حرف و رقم.
- **نشست:** توکن تصادفی ۳۲ بایتی، ذخیره فقط به‌صورت SHA-256، کوکی `HttpOnly` + `SameSite=Lax` + `Secure` اختیاری، انقضا در دیتابیس.
- **CSRF:** توکن per-session در هدر `X-CSRF-Token` برای همه درخواست‌های تغییردهنده؛ صفحه ورود از pre-CSRF cookie استفاده می‌کند.
- **Brute force:** قفل موقت ۱۵ دقیقه‌ای پس از ۵ تلاش ناموفق + محدودیت نرخ ۲۰ درخواست/۱۵ دقیقه برای login به‌ازای IP.
- **SQL Injection:** تمام کوئری‌ها پارامتری هستند.
- **XSS:** خروجی‌ها در سمت کلاینت escape می‌شوند و CSP سخت‌گیرانه (بدون inline script/style) اعمال می‌شود.
- **SSRF:** آدرس‌های خصوصی/رزرو‌شده، localhost و دامنه‌های داخلی به‌طور پیش‌فرض مسدود می‌شوند. IP قبل از اتصال resolve و pin می‌شود. امکان عبور صریح برای هر دامنه یا به‌صورت سراسری وجود دارد.
- **هدرهای امنیتی:** Helmet (CSP، `frame-ancestors none`، `nosniff` و …).
- **Secrets:** فقط از env؛ در API تنظیمات فقط وضعیت و دامنه/فرستنده ماسک‌شده برگردانده می‌شود.

> توجه: اجازه آدرس خصوصی (`allow_private`) را فقط برای سرویس‌های داخلی واقعی فعال کنید.

## API

### احراز هویت

| متد | مسیر | دسترسی | توضیح |
|---|---|---|---|
| GET | `/auth/csrf` | عمومی | دریافت pre-CSRF token |
| POST | `/auth/login` | عمومی | ورود |
| POST | `/auth/logout` | کاربر | خروج |
| GET | `/auth/me` | کاربر | اطلاعات کاربر و CSRF |
| POST | `/auth/password` | کاربر | تغییر رمز خود |

### داشبورد

| متد | مسیر | دسترسی | توضیح |
|---|---|---|---|
| GET | `/dashboard/uptime` | کاربر | داده داشبورد Uptime + خلاصه + sparkline |

```bash
npm run migrate
```

- فایل‌های `migrations/*.sql` به ترتیب نام اجرا و در جدول `schema_migrations` ثبت می‌شوند.

## رفع اشکال

### «اتصال به PostgreSQL برقرار نشد»

- مقدار `DATABASE_URL` را بررسی کنید؛ در Docker باید میزبان `db` باشد، نه `localhost`.
- رمز داخل `DATABASE_URL` باید با `POSTGRES_PASSWORD` برابر باشد.
- `docker compose logs db` را ببینید.

### ادمین ساخته نشد

- `ADMIN_PASSWORD` خالی است یا سیاست رمز را رعایت نمی‌کند.
- کاربری با همان نام از قبل وجود دارد؛ برای بازنشانی از `npm run seed:admin -- --force` استفاده کنید.

### هشدار ارسال نمی‌شود

- در **مدیریت ← تنظیمات ← کانال‌های هشدار** وضعیت کانال را ببینید.
- برای ایمیل هر سه مقدار `SMTP_HOST`، `SMTP_FROM`، `ALERT_EMAIL_TO` لازم است.
- لاگ worker را بررسی کنید: `docker compose logs -f worker`.

### دامنه خصوصی رد می‌شود

- برای همان دامنه گزینه «اجازه آدرس خصوصی» را فعال کنید یا تنظیم سراسری `allowPrivateTargets` را روشن کنید. این کار آگاهانه ریسک SSRF را می‌پذیرد.

### تاریخ‌ها میلادی/شمسی نمی‌شوند

- دکمه «نمایش میلادی/شمسی» در نوار بالا وضعیت را در `localStorage` ذخیره می‌کند. اگر مرورگر حالت private باشد، پس از بستن تب بازنشانی می‌شود.
